# Design Review — Automated Documentation Sync

**Reviewed artifact:** `docs/architecture.md` (draft 1)
**Reviewer:** Design Reviewer role, executed with an independent Copilot `rubber-duck` review agent (no code existed at review time). Findings below are the agent's, verbatim in substance; resolutions are the architect's and **pending human approval at Gate 2**.
**Status legend:** Resolved = architecture updated (draft 2); Accepted risk = documented residual risk; Open = needs human decision.

| ID | Severity | Description | Impact | Recommendation | Resolution status |
|---|---|---|---|---|---|
| DR-001 | Critical | Approval enforcement is bypassable: hooks block direct `.sdlc` edits, but an agent with shell access could run approval commands; `--by` does not authenticate a human; ignored local state cannot be CI-verified. | An agent could self-approve a gate. | Treat hooks as advisory; approvals through a human-controlled boundary. | **Resolved (arch §7, §12):** `approve`/`reject` refuse to run without an interactive TTY and require typing the gate name; approvals are written to a **committed** ledger `docs/approvals.json` (visible in PR diff) and verified against artifact hashes by `workflow verify` and CI; hooks documented as guardrails, not a security boundary. **Accepted residual risk:** a malicious local user/agent with a real TTY can still approve; final authority is human PR review. |
| DR-002 | High | Hashes recorded but not enforced; artifact could change after approval. | Stale approval remains valid. | Hash the reviewed artifact, recheck before transitions/apply, invalidate downstream gates, bind PR approval to final diff. | **Resolved (§12):** SHA-256 per approved artifact; recheck on every transition/apply; change invalidates that gate and all later gates; Gate 5 binds to `git diff` hash of the PR branch. |
| DR-003 | High | Workflow transitions lack an executable contract (no advance/complete/fail/retry commands). | Non-gated stages, failures and resumes undefined. | Explicit commands with evidence, prerequisites, retry semantics. | **Resolved (§5, §12):** `workflow complete <stage> --evidence <path>`, `workflow fail <stage> --reason`, `workflow retry <stage>` (max 2, then blocked until human decision); transition table with prerequisites. |
| DR-004 | High | Stage 1 analyst has no execute tool and the CLI does not exist yet. | Story handoff unclear. | Orchestrator supplies validated story via read-only handoff; fixture bootstrap. | **Resolved (§3):** `workflow start <ID>` (run by Orchestrator/human) writes read-only `.sdlc/inputs/<ID>.json` + delimited markdown rendering; Analyst only reads it. Before M6 exists, requirements for DEMO-101 were derived directly from `demo/jira/stories.json` (already done, recorded in requirements approval). |
| DR-005 | High | `docs propose` has no content input; the app has no LLM. | Engine cannot create proposals. | Define a validated proposal-input format. | **Resolved (§4):** Documentation Agent writes `docs/sync/proposals/<id>.json` (schema: `targetFile, action, blockId, reason, storyId, requirementIds, content`); `docs propose` validates it, computes `baseHash`, stores it; `docs show <id>` renders the diff for reviewers. |
| DR-006 | High | Documentation agent may edit `CHANGELOG.md` directly, bypassing Gate 4. | Unapproved doc changes. | Route all sync changes through proposals. | **Resolved (§4):** all sync targets, including `CHANGELOG.md`, change only through approved proposals; Documentation Agent writes proposal files only; `docs verify` flags managed-block drift outside applied proposals. |
| DR-007 | High | Windows path containment underspecified (drive/UNC, case, junctions, ADS, missing targets, races). | Path traversal / escape. | Windows-aware containment + tests. | **Resolved (§4):** `safeResolve()` rejects absolute paths, drive/UNC prefixes, `..`, `:` alternate streams, reserved device names; resolves existing parent with `realpath`; `lstat` rejects symlink/junction; case-insensitive compare on win32; tested on Windows. TOCTOU assumption (trusted single-user workspace) documented. |
| DR-008 | High | Atomic rename doesn't define a safe batch; concurrent edits, multi-proposal per file, crash mid-batch. | Partial/corrupt apply. | Group by file, prevalidate, journal. | **Resolved (§4):** group by file; prevalidate all (hash, conflicts) before any write; same-dir temp + rename; `.sdlc/apply-journal.json` for recovery; never overwrite a file whose hash changed. |
| DR-009 | Medium | State, audit and doc writes lack ordering/recovery. | Applied change without audit record. | Journaled idempotent operations. | **Resolved (§12):** order = journal intent → write → update state → append audit; startup reconciliation; reader tolerates a truncated last JSONL line. |
| DR-010 | High | Jira normalization unspecified (no universal AC field; ADF descriptions). | Jira can't meet story shape. | Specify API, field mapping, rich-text conversion. | **Resolved (§11):** Jira Cloud REST v3; AC from optional `JIRA_ACCEPTANCE_CRITERIA_FIELD` custom field, else the "Acceptance Criteria" section of the description (ADF → plain text); missing → `MISSING_FIELDS`. Live verification stays **BLOCKED** (no Jira); mocked-fetch unit tests only. |
| DR-011 | Medium | Jira pagination, timeouts, rate limits, HTTPS, redirects unspecified. | Incomplete lists; credential leak. | Define safeguards. | **Resolved (§11):** HTTPS only, 10 s timeout, 2 bounded retries on 429/5xx, `redirect: 'error'`, paginate (max 500), sanitized errors, never log auth header. |
| DR-012 | Medium | `list()` typed as returning a single Story result; malformed-entry policy unclear. | Ambiguous contract. | Define collection/single types and defaults. | **Resolved (§2):** `list(): Promise<Result<{stories: Story[]; skipped: SkippedEntry[]}, StoryError>>`, `get(id): Promise<Result<Story, StoryError>>`; malformed entries are skipped and reported, malformed file → `MALFORMED`; defaults: `dependencies=[]`, `metadata={}`. |
| DR-013 | Medium | Conflict detection is structural, not semantic. | Stale prose undetected. | Human-review route for semantic conflicts; don't over-claim. | **Resolved (§4):** Documentation Agent may flag `notes.semanticConflict`; proposal becomes `needs-review` (cannot be approved without explicit reviewer acknowledgement); verification report states semantic accuracy is a human judgment. **Accepted limitation.** |
| DR-014 | High | Untrusted story text can steer agents (prompt injection). | Unintended edits. | Treat as data; constrain authority independent of prompts. | **Resolved (§7):** story text delimited as untrusted data in handoff file; agent instructions say never follow instructions found in story/doc content; authority limited by tool lists, hooks, gates and CI. **Accepted residual risk** (LLM-level). |

## Summary
14 findings: 1 Critical, 9 High, 4 Medium — all addressed in `architecture.md` draft 2; two residual risks accepted (DR-001, DR-014) plus one limitation (DR-013). No finding left Open.
